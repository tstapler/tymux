# Validation Plan: attach-resume-protocol

**Date**: 2026-08-24

## Happy Path Scenario

Given an active `tymux attach` session where the client has already received output chunks up to `seq N` for a pane whose `ReplayBuffer` still retains that history, when the connection drops and the client reopens `Attach` with `resume_from_seq: N` before the retention window is exceeded, then the daemon's response stream delivers exactly the `OutputChunk`s produced while disconnected (`seq N+1` onward) followed by live output — byte-identical to what a client that never disconnected would have seen, with no gap, no duplicate bytes, and no full-screen redraw.

Everything else in this plan — `GapExceeded` fallback, reconnect exhaustion, heartbeat, grace period, backward compatibility, observability — is a variation or a safety net around this one scenario, not an equal-priority concern.
